# 人生 CFO · 产品规划

版本：v0.9.0-rc.1 · 最后更新：2026-11-17

背景参考：[原始提纲快照](BACKGROUND.md)。提纲不替代用户当前请求；本页说明实际范围，规则参数与来源见 [DATA](DATA.md)。

## 背景与定位

投资入门产品常把财富变化简化为收益排名，忽略工资、消费、保障、负债与家庭责任。人生 CFO 让玩家在同一家庭的连续选择中看到这些因素如何共同改变财富与生活，并通过完整账本解释结果。

长期方向是从初入职场到退休的约 60 次关键选择。当前聚焦一条可完整游玩、结果可复核的成长线：中文界面、美国资产背景、美元计价、虚构港湾城家庭。角色、工资、住房、车辆、保险与家庭事件都是教学模型，不代表中国家庭的真实投资条件。

差异化来自三点：投资与家庭取舍相连；AI 既给建议又管理独立账户；年度复盘将工资积累和投资表现分开。时代影像与原创旁白帮助理解背景，不为资产增加隐藏收益。

## 当前范围

| 模块 | 已实现行为 | 边界 |
| --- | --- | --- |
| 二十年旅程 | 30 岁、10 万美元起步；2007–2026 共 20 轮，每年两项家庭方案，困难时可暂缓 | 2007–2025 为历史市场，2026 为架空情景，不是预测 |
| 年初情报 | 公开简报、带时点市场数字，以及人机共用的三条匿名机制摘要 | 年末才揭晓当年行情与事件；匿名不能保证模型忘记历史 |
| 投资配置 | 四张主牌对应现金、宽基、科技、消费、医疗、国债、黄金七类资产；比例合计 100% | 无个股、卖空或投资杠杆；板块与宽基可能重叠 |
| 交易与生活 | 年度再平衡或维持持仓；模拟医疗保障、自住房按揭、车辆维护折旧 | 没有现金下限；不支持卖房卖车、提前还贷或历史保单复刻 |
| 三种模式 | 自主选择、采纳并修改建议、托管执行玩家建议 | 托管仍由玩家手动推进回合；同桌使用自己的账本和决定 |
| AI 与规则 | EFUND，默认 gpt-4o，可填账号已开通的模型；未连接时使用规则陪练 | 模型权限由服务商决定；失败后明确重试或选择规则，不隐式替代 |
| 双账本 | 同起点、同市场、同外生事件，分别选择家庭方案和持仓；一起结算提交 | 收入和开支可不同，净资产差距不能单独归因于配置 |
| 年度复盘 | 收支、金融回报、九项资产与两项负债的年初／年末余额、财富曲线 | 余额变化不误称投资收益；按揭本金与利息分列 |
| 模拟参照 | 固定 55 种虚构策略，按同年税费前金融回报比较 | 非真实中国散户或 A 股统计；并列不算“超过”，无本金不排名 |
| 行为画像 | 模型或规则总结本局风格，引用至少三个不同回合的真实记录 | 程序按证据 ID 绑定原文与年份；不是人格或心理诊断 |
| 时代收藏 | 回合地图、相册、展示徽章；照片、历史图解与模拟封面分别标识 | 只解锁已发生年份；徽章不改变结算或得分 |
| 保存与导出 | 当前浏览器自动保存、v3 双账本重放核验、JSON 留档、旧版原档封存 | 无导入或跨设备同步；静态源码不是竞赛防作弊系统 |

三个挑战分别为全程无缺口借款、净资产达到 100 万美元、生活满意度达到 75 且没有未偿还缺口借款。住房按揭不计入缺口借款；未完成全部挑战也可通关。

## 财务一致性

`dist/engine.js` 是财务规则唯一实现，界面展示引擎结果。每轮按以下顺序执行：

1. 校验家庭选择、配置与购置预算，支付年初选择和房车购置；必要时按比例出售金融资产筹资。
2. 年度模式执行目标配置并计成交费用；维持持仓不执行目标比例，也不补现金。
3. 对实际金融持仓应用当年回报，计算房价变化、车辆折旧和按揭本息。
4. 结算工资、生活支出、保障赔付与家庭事件；现金不足时卖出金融资产，仍不足才新增缺口借款，有结余则偿还旧缺口债务。
5. 更新下一年家计与生活值，保存完整快照并核验恒等式。

每年必须满足：**年末净资产 = 年初净资产 + 家庭净投入 + 投资与资产变动**。金融组合回报以年初购置与交易后的实际投资本金计算，不含工资、房车或家庭现金流；费用另列。满意度限制在 0–100，复盘记录实际变化。

规则陪练只依据当前家计和可选方案行动，不读取未来市场。2007–2018 行业使用 French 研究组合，2019–2025 使用 SEC 披露的 XLK/XLY/XLV 代理，两阶段存在口径断点；2026 全部回报为架空情景。

## AI、封存与存档

每轮一次成功请求同时给出情报分析、玩家建议和同桌决定。观察原文由 `signalId` 绑定，画像原文由 `factId` 绑定；额外提供的冲突事实仍拒绝。配置、家庭方案和购置能力交给引擎核验，自由推理不因此被认定为正确。

成功结果绑定当前公开上下文并封存，刷新、换模式或改连接不能重抽；连接变更只影响尚未封存的回合。双方结算原子提交，恢复时逐年重放，并核对同桌是否执行封存决定。

当前仅支持 EFUND 固定 HTTPS 上游。密钥只留页面内存，通过游戏中继的 POST 请求体临时传入，再转为上游 Bearer 认证；不进入 localStorage、存档、导出、仓库、正文日志或缓存。端点和模型偏好可保存，刷新需重填密钥；旧非 EFUND 偏好迁回默认，不改变历史封存结果。

同次操作最多 3 次请求。可选参数兼容、精确匹配的非 JSON 520 和响应头前连接重置共用次数与 60 秒预算；中继不叠加重试。费用按服务商计，恢复也可能重复计费。完整传输边界见 [RELEASE](RELEASE.md)。

v0.9 保持 v3 财务规则、数据版本、存档键和旧上下文标识兼容；v1/v2 原档仅封存，不默默套用新规则重算。导出不含凭证或连接偏好，当前不支持文件导入。
