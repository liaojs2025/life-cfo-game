### 线上运行时兼容复查

首次生产部署页面返回 200，但实际 AI 中继返回安全泛化的 502，尚未构成线上 AI 成功证据。[Cloudflare 官方变更记录](https://developers.cloudflare.com/changelog/post/2024-11-11-cache-no-store/) 说明 `RequestInit.cache` 需相应兼容日期或标志，旧运行时会抛错。当前托管入口未暴露此配置，因此实现已从 Worker 上游调用移除该属性，改用 POST、Authorization 及 `Cache-Control: no-store` 请求头，响应仍禁止缓存；调用显式绑定 `globalThis`。

后续核对 [Cloudflare Request 官方文档](https://developers.cloudflare.com/workers/runtime-apis/request/) 确认 Worker 不支持 `redirect: 'error'`，在构造请求时即抛出 TypeError，与生产日志中的极短失败耗时相符。实现已改为 `manual`，对所有 300–399 状态立即取消响应体并返回 502，不跟随任何 Location，凭证只发往固定目标。浏览器直连请求仍使用其运行时支持的 `error`。

独立回归使用会拒绝 `options.cache` 与 `redirect: 'error'`、且要求正确 `this` 的旧运行时替身；转发成功，同时检查固定目标、Bearer、POST 与双向 no-store。另用 300、301、302、303、307、308、399 响应提供恶意 Location 和含假密钥的响应体，逐项验证上游只调用一次、响应体被取消、响应不含 Location、Set-Cookie 或凭证。错误诊断只允许固定类别和词表标记，密钥及任意私密文字夹入缓存、TLS、绑定与重定向异常均不泄露。全部 90 项通过支持兼容修正的代码行为。主 agent 在发布提交 `da868b7d743c35dddf4f5125ccc980c46e1368e9` 后确认：原私有站点的生产 `/api/ai` 经 EFUND/gpt-4o 真实返回 3 条分析与模型来源标记。凭证经隐藏标准输入进入内存，不写日志；独立审计 agent 未接触实际凭证。本次仅据该生产验收记录更新状态，代码未变，未重复运行测试。
